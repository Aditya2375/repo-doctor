# Repo Doctor: the inspection bench

Status: staged locally. No push or deployment.

## Product truth
A bounded, deterministic pattern-rule review of public GitHub repositories. Architecture, security, performance and style are rule groups, not people or independent models. A score is a rule score, never proof of safety. Reads are pinned to an immutable commit, with partial coverage made explicit. Existing 160-file, 150,000-byte-per-file and 20-second request limits stay visible.

## Direction
An application-first inspection bench. White and graphite surfaces, acid-yellow markers, square geometry, compact sans typography, a ruled technical grid and an actual source specimen. Not another dark marketing hero, large serif editorial or oversized grotesque slogan. The first screen puts the repository input next to a working, clearly labelled local example.

The mark is an original bracketed cross. Monospace is for actual source, paths and revision data, not decorative marketing eyebrows. The report uses an instrument-like four-column score strip and severity-coded finding rows, not a generic feature-card grid. Navigation and controls have real jobs.

## Interaction
The source specimen is not a screenshot or invented report. Tabs select real bundled sample files. Findings are computed by the same rule engine as repository reviews. Applying a sample fix changes actual sample code and re-runs the rules. The local example needs no GitHub requests and is clearly labelled throughout its report and exports.

Actual review work runs off the UI thread, with cancellation and a bounded deadline. Motion is restrained: source selection, real progress, short entrance transitions. Reduced motion remains usable. No scroll hijack, animated wallpaper, copied component or runtime animation dependency.
